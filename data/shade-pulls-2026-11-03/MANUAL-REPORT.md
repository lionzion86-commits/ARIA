# Manual shade curation — 2026-11-03 (Danny's directive: read the page, write it down)

Automated pulls left **187 gated listings** without shade data. This pass curated them by hand: open the product's own retail page (or, where the retailer walls its pages, search-indexed retailer/brand pages for the same product), transcribe the shades **verbatim**, and write them in the same ingest shape as the morning pull. No Apify, no scraping actors.

## Rules applied

- A shade name/number is recorded **exactly as the store writes it**. Nothing invented, translated, or guessed; per-shade price/stock left null unless the page showed them plainly (in the event, none were written).
- **Sephora / Ulta / Walmart / Costco / Victoria's Secret:** a shade enters the dataset only with BOTH its verbatim name AND its own per-shade SKU/URL actually seen (skuId, sku, item id, VS choice URL). Sibling shades seen by name only are listed in the per-product table as names-only evidence — they do NOT enter the dataset, because their SKUs cannot be fabricated.
- **YesStyle exception (verified by three independent passes):** modern YesStyle listings use **one pid per product family** — the URL slug changes per shade, the pid never does (confirmed against asianbeautywholesale.com, YesStyle's own wholesale mirror, which carries the same catalog numbers). There is no per-shade pid to capture. Shades transcribed verbatim from the family's own catalog page / mirror page therefore enter the dataset as variants of the family pid — the shade genuinely lives on that one page, which is exactly the case Danny's directive covers. Each family's evidence URL is in the table below.
- Multipacks keep the shade and add `multipack_quantity-N` (Costco/Walmart packs).
- Products with no color axis at all (translucent powders, size-only correctors, hair treatments, moisturizers, fixed gift sets) were resolved as **no shade axis** — no dataset record, evidence noted; the gate can lift on them honestly because there is no tono to pick.
