# Sourcing audit step 2: REMOVE-store products ported to live lanes (#443)

Generated by `node scripts/port-offsale-to-live.mjs` from the catalogues in this repo. No network, no scraping.

## Rules applied

- A product from an off-sale store ports only when the SAME product is already in a live lane's catalogue here.
- The live record stays the retailer of record, at the live lane's own price. The dead store's price, URL and name are never carried.
- Same product means a shared GTIN, or a shared model/style/set code plus the same brand, a strong title match, a compatible variant set (colour, capacity, pack size, size run) and a sane price ratio. The code must name one product on each side. Name similarity alone never matches.
- Only fields the live record lacks are filled: photos, a measured weight, a Spanish description (an English one only as `description_en`), and variant attributes the live title already states. Sizes are never ported: the live retailer's sizes win.
- Products with no match stay off sale, data retained.

## The Barbie Royal trap (c.6299236303)

Target's "Barbie Royal Doll with Brightly Highlighted Hair, Butterfly-Print Skirt and Accessories" and Walmart's "Barbie Royal Fashion Doll with Blonde Hair, Removable Skirt & Accessories [Walmart Exclusive]" are different dolls. Neither carries a GTIN or a model code, so they do not match. The Target doll stays off sale, and the Walmart doll keeps its own price and data. `scripts/test/port-tests.mjs` pins this.
